# 时间切片批量读取、范围与缓存

时间切片按实际 INLINE/XLINE 范围读取。原始 SEG-Y 保持外部只读引用，不复制整块地震体，也不把全体振幅存入数据库。此次缓存只在进程内，退出程序后释放，不增加磁盘缓存文件。

## 读取选项

`TimeSliceReadOptions` 保留原有精度与预算字段，增加以下选项。`readSeismicTimeSlice` 按原文件的毫秒采样轴工作；`readTimeSlice` 仍要求确认坐标、时间单位和参考面。

| 字段 | 默认值 | 含义 |
|---|---:|---|
| `inlineMin / inlineMax` | 无限制 | 实际 INLINE 号的闭区间，不是数组下标 |
| `crosslineMin / crosslineMax` | 无限制 | 实际 XLINE 号的闭区间 |
| `ioMode` | `auto` | 自动选可用通道；可显式指定 `buffered`、`mapped` 或对照用 `legacy` |
| `workerCount` | 2 | 1、2或4个工作任务；每个任务有独立只读句柄/视图 |
| `tileSize` | 128 | 范围32–512，每块最多`tileSize²`点；规则体沿文件快轴组成长条，不改变采样精度 |
| `useCache` | true | 使用进程内相邻时间带缓存 |
| `adjacentSamples` | 4 | 一次获取1–16个相邻样点；时间带按样点编号对齐 |
| `cacheBudgetMiB` | 512 | 进程内LRU缓存预算，0禁用，最大1024MiB；不代表进程总内存上限 |
| `collectTimings` | false | 开启详细阶段计时，主要用于性能诊断 |

`fullResolution=true` 保留请求区域内的全部实际网格点。范围裁剪不属于降采样，`nativeInlineCount / nativeCrosslineCount` 描述裁剪后、预览抽样前的网格数量。`maxValues` 始终有效；超限报错，不悄悄降低高清精度。

## 三种读取通道

- `legacy` 保留逐道通用接口的数值路径，用作正确性和性能对照。
- `buffered` 把按物理文件位置组织的请求合并到有界连续缓冲中，再提取目标样点。读入的字节可能更多，但减少小请求及临时分配。
- `mapped` 在 Windows 使用只读文件视图。映射窗口有界，不要求将整个文件装入物理内存。映射访问仍可能触发磁盘缺页，不能据此承诺任何文件都瞬间打开。

每条实际读取的道仍核对采样轴、测线编号及来源坐标语义。缺道保持 NaN，零值和负振幅不被当作缺失。批量转换保留原先支持的固定道长格式及大小端语义。

对已确认规则道序的矩形网格，分块沿文件中的连续快轴延伸，并按正向或反向的物理道序安排任务，减少方形块跨多条测线反复跳读。返回的数组和回调偏移始终按IL/XL升序组织。无法确认规则道序时保留方形分块；分块形状不是对外数据分辨率，也不保证固定宽高。

工作任务返回完整分块后，协调线程写入最终矩阵。用户进度和取消回调在发起服务调用的线程执行，工作任务不直接调用GUI。取消/失败不发布部分最终结果，已完整校验的缓存块可以保留。

## 渐进显示与缓存

两个切片方法都在取消回调之后接受可选 `TimeSliceTileCallback`。分块包含整体尺寸、行列偏移、当前时间面的振幅与完成进度。回调不是最终成功信号；GUI须明确区分“正在加载”和“完整结果”，取消或失败时清除临时显示，完成前不导出为完整图片。

缓存保存真实 float 时间带与坐标，未缓存PNG替代振幅。时间样点按 `floor(sampleIndex / adjacentSamples)` 归组，因此附近时间若落在同一组可以复用；跨组或超过容量仍需读源文件。缓存按来源身份、区域、时间带及校验约定区分，来源变化必须先核对/重导入，不能借缓存绕过来源检查。

缓存是有界LRU：若区域总缓存超过预算，较早块会被淘汰；整幅大切片连续浏览不一定全部命中。为了提高局部浏览的命中率，可缩小ROI，或在明确内存预算后调整时间带宽度与容量。每次完整返回仍有输出数组、坐标数组和显示图像开销。

同一进程中的不同 `DataService` 实例可复用有效缓存。`DataService::clearSeismicSliceCache()` 清空该缓存，不修改源文件。当前不提供跨进程持久化缓存。

来源身份使用规范路径、大小、修改时间及首尾各64KiB的摘要，不扫描整个体。若外部工具原地改写文件中部，还刻意保留大小、修改时间和首尾内容，无法靠此摘要识别，须停止读取、清空缓存并重新导入。缓存预算只约束缓存持有的块；输出矩阵、正在读取的块和GUI图像另外占用内存。

## 小范围基准工具

编译目标为 `timeslice_benchmark`，它只通过公开接口读取已导入工区。所有路径与编号由调用者提供；输出JSON到标准输出，未自动保存任何真实数据或结果文件。

```text
timeslice_benchmark <工区目录> <地震体编号>
    --inline-min <实际IL起点> --inline-max <实际IL终点>
    --crossline-min <实际XL起点> --crossline-max <实际XL终点>
    --time <毫秒> --deadline-seconds 30 --tile-size 64 --repeats 1
```

默认最多选择每轴前256个位置，振幅预算为65536点。增加范围时必须明确增加 `--max-cells`，工具最多允许400万点。每次读取默认30秒协作式取消期限；正在执行的系统读取不保证能在到期的那一毫秒立刻返回。规则步长不能确定时应显式提供范围。

测试顺序：

1. `legacy` 单线程建立当前范围的参考矩阵。
2. 每轮重新运行 `legacy` 单线程，以及 `buffered` 与 `mapped` 的1、2、4线程，便于比较预热后的同时间面读取。
3. 比较每个振幅的位值（双方NaN视为同一缺失）、全部实际XY和测线轴。
4. 建立相邻时间的独立参考，再测试缓存填充、同时间命中和同时间带内的相邻样点命中。

使用 `--repeats 2` 等选项可重复并轮换候选顺序。工具**不清空操作系统文件缓存**，后运行的案例可能受益于前面的读取；输出明确标记这一点。服务的切片缓存关闭不等于操作系统冷缓存。不能把一次后运行的成绩直接解释为首次读取的加速倍数。

详细计时本身有开销。完成阶段诊断后，可加 `--no-stage-timings` 单独复测总吞吐量；此时阶段时间为0，墙钟时间和逻辑计数仍可检查。也不要把开启和关闭阶段计时的成绩混作同一条件。

结果字段中，`wallMs` 是调用总墙钟耗时；`workerPositionMs / workerReadMs / workerValidationMs / workerConversionMs` 是各工作任务对应阶段累计的耗时，可能大于墙钟时间，也不是CPU使用率。`explicitBytesRead` 是显式缓冲读取量，`viewBytesMapped` 是映射视图长度累计值，均不能当作物理磁盘实际流量。

阶段统计覆盖分块定位和批量读取通道，不含来源核验、Reader打开时的几何探测、调度及最终拼装，所以四项之和并不等于总耗时。每次切片调用按并发槽复用有界 Reader 池；同一槽的瓦片不再重复打开文件和探测几何，不同槽仍持有独立只读句柄且不会并发使用同一 Reader。`clearSeismicSliceCache()` 清除调用时已有条目，在途读取完成后仍可能填入新的完整块。

默认基准不会扫描整个文件或创建整个体的副本。需要检查真实大体时先从小区域开始，核对全部值一致后再扩大范围；首次完整切片仍有跨大量道访问的成本。

完整调用例子见 [案例11](../examples/getting_started/11_time_slice_region/main.cpp)。测试目标 `timeslice_batch_tests` 自动在临时目录生成格式/大小端、缺道、物理排序和变化来源场景，不依赖真实测区资料。
