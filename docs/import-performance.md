# 多线程与增量导入

“打开工区”只连接已有数据库并查询资料目录；“导入目录”才扫描和解析原文件。继续使用已入库资料时无需重复导入。

## 处理流程

扫描目录后，工作线程并行检查文件变化、计算普通来源完整 SHA-256，并解析需要更新的文件。协调线程按原文件排序复制来源并写入 SQLite，避免线程完成先后改变归井、来源编号或冲突处理结果。

目录导入的 `parserThreads` 限制为 1～4，界面提供 1/2/4，默认 2。大表格、内存展开、磁盘带宽和串行写入都会限制收益，线程数量不等于加速倍数。Windows 完整 SHA 使用系统实现，不可用时回退兼容实现。

## 推荐设置

| 设置 | 作用 |
|---|---|
| 引用原文件 | 界面默认，避免普通来源复制；路径需持续可访问 |
| 复制普通资料 | 便于搬移工区，增加空间和读写开销；SEG-Y 始终外部引用 |
| 2 个线程 | 默认准备并发数 |
| 1 个线程 | 串行对照或减少磁盘争用 |
| 4 个线程 | 增加文件准备并发，实际效果需用相同条件对比 |
| 完整校验每个文件 | 重算普通来源 SHA；未变文件仍可跳过解析 |

公开 C++ `copySources` 为兼容已有调用仍默认 `true`，需要引用模式时明确设为 `false`。

## 增量检查边界

已成功导入的文件先通过路径、大小、时间及首/中/尾有界内容指纹检查，解析配置也参与复用判断。检查相同则直接使用已保存对象；失败文件不会当作成功缓存跳过，强制新批次和明确重导入也不会走普通缓存跳过。

这不是逐字节完整性审计。如果内容改变，但被检查的时间信息和抽样区间同时保持不变，快速检查可能发现不了；需要完整核验时设置 `verifyUnchangedFiles=true`。旧工区首次升级扫描需要建立已核验缓存。

SEG-Y 保留文件头、大小和修改时间等有界身份检查，即使开启完整校验也不会通读或复制整个地震体。

## 内存、取消和进度

`maxPendingBytes` 默认 256 MiB，是正在准备及已完成等待入库任务的估计预算，实际取值限制在 8 MiB～1 GiB，**不是进程内存硬上限**。达到 32 MiB 的压缩表格或未知大文件单独准备；XML/LAS 按流式展开估算，在预算允许时并行。只登记的照片、归档和有界地震头仍可并行检查。单个复杂工作簿仍可能展开为较大对象。

原始单元格、层位点、层段和测量值使用 `execBatch()` 按 256 行一批写入，减少逐行 SQL 调用；每个批次重新准备同一 SQL，保留错误处理与中途取消。每文件事务独立提交。取消时停止新任务、等待工作线程退出，未发布对象不入库，之前成功提交的文件保留。进度与取消回调只在调用线程执行，工作线程读取共享取消状态。

扫描、校验、解析、复制、入库阶段可在进度中区分。`ImportReport.elapsedMs` 是用户等待的总时间；其他阶段时间是逐文件累计值，并行时存在重叠，不能相加当作总时间。

## C++ 设置

```cpp
paleo::data::ImportOptions options;
options.copySources = false;          // 引用来源，避免复制。
options.parserThreads = 2;            // 目录导入准备线程数。
options.verifyUnchangedFiles = false; // 默认增量检查。

paleo::data::ImportReport report;
std::string error;
bool ok = service.importDirectory(inputDirectory, options, report, error);
if (!ok) {
    // 查看 error 与 report.errors；已成功提交的文件仍然保留。
}
// report.cached 是 skipped 中通过增量检查复用的数量。
// report.workerCount 是配置上限，不是每时每刻实际活动线程数。
```

此处假定 `service` 已打开工区。`parserThreads` 作用于目录导入，单文件导入不会因此拆为多个解析任务。

命令行可使用：

```text
paleo_data_cli audit <输入目录> <工区目录> --reference-sources --threads 2
paleo_data_cli audit <输入目录> <工区目录> --reference-sources --threads 4 --verify-all
```

对比性能时使用相同输入和复制选项，首次导入分别建立新工区。还需核对对象、数值和失败记录一致，记录缓存与磁盘活动影响。仓库不携带任何真实目录性能报告或导入结果。
